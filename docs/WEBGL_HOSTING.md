# Unity WebGL 빌드 호스팅 기능

## 개요
Shareify에 Unity WebGL 빌드를 업로드하고 브라우저에서 직접 플레이할 수 있는 기능이 추가되었습니다.

## 주요 기능

### 1. WebGL 빌드 업로드
- 파일 업로드 시 "Unity WebGL 빌드" 체크박스를 통해 WebGL 빌드임을 표시
- 업로드 전 자동으로 WebGL 빌드 검증 수행
  - ZIP 파일 내부의 필수 파일 확인 (.data, .wasm, .js)
  - 유효하지 않은 빌드는 업로드 거부
- 종단간 암호화(E2EE)와 호환
  - WebGL 빌드도 암호화하여 업로드 가능
  - 플레이 시 자동으로 복호화

### 2. WebGL 빌드 플레이
- 파일 상세 페이지에서 "게임 플레이" 버튼을 통해 게임 실행
- 파일 목록에서도 직접 플레이 가능
- 브라우저 내 캐싱 지원
  - IndexedDB를 사용한 로컬 캐시
  - 한 번 다운로드한 빌드는 캐시에서 로드하여 빠른 시작
  - 캐시 관리 기능 제공 (삭제 가능)
- 진행률 표시
  - 다운로드, 압축 해제, 로딩 진행 상황 실시간 표시

### 3. 암호화된 WebGL 빌드 플레이
- 암호화된 빌드는 플레이 시 복호화 키 입력 요구
- 올바른 키 입력 후 자동으로 복호화 및 실행
- 복호화된 데이터는 메모리에만 존재, 디스크에 저장되지 않음

## 사용 방법

### WebGL 빌드 업로드
1. Unity에서 WebGL 빌드 생성
2. 빌드 폴더를 ZIP으로 압축
3. Shareify 파일 업로더에서 압축 파일 선택
4. "Unity WebGL 빌드" 체크박스 선택
5. (선택사항) 암호화가 필요한 경우 "종단간 암호화(E2EE)" 활성화
6. 업로드 버튼 클릭

### 게임 플레이
1. 업로드된 WebGL 빌드 파일 선택
2. "게임 플레이" 버튼 클릭
3. (암호화된 경우) 복호화 키 입력
4. 게임 로딩 대기
5. 게임 플레이

### 캐시 관리
- 게임 플레이 중 "캐시 삭제" 버튼으로 로컬 캐시 제거
- 캐시 삭제 후 다음 플레이 시 다시 다운로드 필요

## 기술 스택

### 클라이언트
- **JSZip**: ZIP 파일 압축 해제
- **IndexedDB**: 브라우저 로컬 캐싱
- **Unity WebGL Build API**: Unity WebGL 빌드 로더 (Unity 2020.1+)

### 서버
- **MongoDB**: WebGL 빌드 메타데이터 저장
- **Cloudflare R2**: WebGL 빌드 파일 저장
- **파일 검증**: 업로드 시 WebGL 빌드 구조 검증

## 파일 구조

### 새로 추가된 파일
```
src/
├── lib/
│   └── webgl/
│       ├── validation.js    # WebGL 빌드 검증 로직
│       └── player.js         # WebGL 플레이어 및 캐싱 로직
├── app/
│   └── play/
│       └── [hash]/
│           └── page.jsx      # WebGL 플레이어 페이지
└── models/
    └── File.js               # WebGL 관련 필드 추가
```

### 수정된 파일
```
src/
├── app/
│   ├── components/
│   │   ├── fileUploader.jsx  # WebGL 체크박스 추가
│   │   └── fileList.jsx       # WebGL 배지 및 플레이 버튼 추가
│   └── file/
│       └── [hash]/
│           └── page.jsx       # 게임 플레이 버튼 추가
└── actions/
    └── files.js               # WebGL 관련 액션 추가
```

## API 엔드포인트

### 업로드
- `uploadFile()`: WebGL 빌드 업로드 (isWebGLBuild 파라미터 추가)

### 조회
- `getFileDetails()`: WebGL 빌드 정보 조회 (isWebGLBuild 필드 포함)
- `getFileDownloadUrl()`: WebGL 빌드 다운로드 URL 생성

## 제한사항

### 파일 크기
- WebGL 빌드는 일반적으로 큰 용량
- 사용자의 저장소 한도 내에서만 업로드 가능
- 브라우저 캐시 용량 제한 고려 필요

### 브라우저 호환성
- 최신 브라우저 권장 (Chrome, Firefox, Edge, Safari)
- IndexedDB 지원 필수
- WebAssembly 지원 필수

### Unity 버전
- Unity 2019.4 이상에서 빌드된 WebGL 권장
- 최신 Unity 버전의 WebGL 템플릿 사용 권장

## 보안

### 파일 검증
- 업로드 시 ZIP 파일 구조 검증
- 필수 WebGL 파일 존재 확인
- 악성 파일 업로드 방지

### 암호화
- E2EE 지원으로 서버에서 내용 접근 불가
- 클라이언트 측 암호화/복호화
- 암호화 키는 사용자만 보유

### 접근 제어
- 파일 소유자만 플레이 링크 접근 가능
- 공개 설정 시 다른 사용자도 플레이 가능
- 공유 기능을 통한 선택적 접근 허용

## 성능 최적화

### 캐싱 전략
- 첫 다운로드 후 IndexedDB에 캐시
- 동일 빌드 재실행 시 즉시 로드
- 캐시 크기 모니터링 및 관리

### 압축 해제
- 클라이언트 측에서 ZIP 압축 해제
- 서버 부하 최소화
- 브라우저 Web Worker 활용 가능

### 로딩 최적화
- 진행률 표시로 사용자 경험 향상
- 단계별 로딩 (다운로드 → 압축 해제 → 초기화)
- 비동기 처리로 UI 블로킹 방지

## 향후 개선 사항

1. **자동 업데이트 감지**: 동일 빌드 업데이트 시 캐시 자동 갱신
2. **멀티플레이 지원**: Unity Netcode 또는 Mirror Networking을 통한 멀티플레이어 기능
3. **통계 수집**: 플레이 횟수, 플레이 시간 등 통계
4. **미리보기 이미지**: 빌드 업로드 시 스크린샷 첨부
5. **임베드 기능**: 외부 사이트에 게임 임베드 가능한 iframe 제공
6. **버전 관리**: 동일 게임의 여러 버전 관리

## 트러블슈팅

### 게임이 로드되지 않는 경우
1. 브라우저 콘솔 확인
2. WebGL 빌드가 올바르게 압축되었는지 확인
3. 캐시 삭제 후 재시도
4. 브라우저 업데이트 확인

### 암호화된 게임 복호화 실패
1. 올바른 암호화 키 입력 확인
2. 업로드 시 사용한 키와 동일한지 확인
3. 파일이 손상되지 않았는지 확인

### 캐시 문제
1. 브라우저 설정에서 IndexedDB 사용 허용 확인
2. 충분한 디스크 공간 확보
3. 브라우저 캐시 수동 삭제 시도
