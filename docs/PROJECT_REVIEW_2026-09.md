# 프로젝트 점검 기록 (2026-09)

에디터 제목 크기 오류를 시작으로 인증, 파일·디렉터리 공유, 업로드·다운로드,
AI 연동, 미리보기, DB 연결, 의존성을 점검했다. 아래 기록은 코드 검토와
명시된 테스트 범위의 결과이며, 운영 계정과 실제 저장소를 이용한 전체 통합 테스트를 의미하지 않는다.

## 개선 항목

- 에디터: Tailwind 기본 스타일 때문에 같아진 제목 크기를 단계별로 지정했다.
  자동저장 타이머와 저장 중 추가 편집 처리를 개선하고, 중복 저장과 암호 없는 암호화 문서 저장을 막았다.
  문서 최초 렌더링의 HTML을 정화하고 HTML 내보내기에서 코드와 속성을 이스케이프한다.
  코드 블록 원문은 유지한다.
- 업로드: 같은 이름의 파일도 독립적으로 진행률과 실패 상태를 관리한다.
  AI 인덱싱 실패가 이미 완료된 파일 업로드를 실패로 바꾸지 않도록 했다.
- ZIP 다운로드: 폴더 구조와 중복 이름을 보존하며, 일부 파일이 실패한 ZIP을 완료로 처리하지 않는다.
- 인증 이동: 로그인 후 이동 경로를 서비스 내부 경로로 제한한다.
- 인증 토큰: 비밀번호 재설정과 이메일 인증 토큰을 정해진 길이의 hex 문자열로 검증한다.
  이미 활성화된 2단계 인증을 새 설정 요청으로 덮어쓰지 못하게 한다.
- 공유·파일 API: 식별자의 형태를 검증하고, 공유 링크의 해시와 만료일이 같은 링크에 속하는지 확인한다.
  에디터 첨부 미디어는 부모 문서와의 연결 및 접근 권한을 확인한다.
- CLI 업로드: access token을 확인하고, 상위 폴더 쓰기 권한과 파일 크기 검증을 보강한다.
- AI: 파일 접근 권한을 서버에서 확인하고 DB 메타데이터를 사용한다.
  암호화 파일의 인덱싱을 차단하며 검색 결과에도 현재 파일 권한을 적용한다.
- DB: 실패한 연결 Promise가 캐시에 남아 이후 요청까지 계속 실패하는 문제를 수정한다.
- WebGL: 업로드된 실행 코드를 별도의 sandbox iframe에서 실행하도록 변경한다.
- PDF: 응답 내용을 확인하고 PDF MIME 타입으로 고정한 Blob을 브라우저 뷰어에 전달한다.
  HTML·텍스트 미리보기에는 sandbox를 적용한다.
- 접근성: 모바일 화면 확대 제한을 해제하고 Next.js viewport 선언을 분리한다.

## 의존성

Node.js 22.x를 배포·로컬 기준으로 명시했다. Next.js와 eslint-config-next는
15.5.25, Mongoose는 8.24.4, Nodemailer는 10.0.1로 업데이트했다.
AWS SDK v3를 업데이트하고 사용하지 않는 v2 패키지를 제거했다.
React 18과 Next.js 15의 메이저 버전은 유지했다.

검토한 공식 보안 공지에는 [Next.js Server Actions DoS](https://github.com/vercel/next.js/security/advisories/GHSA-m99w-x7hq-7vfj),
[Mongoose](https://github.com/Automattic/mongoose/security/advisories/GHSA-664h-wqgq-64gw),
[AWS SDK 전이 의존성의 XML parser](https://github.com/NaturalIntelligence/fast-xml-parser/security/advisories/GHSA-m7jm-9gc2-mpf2)가 포함된다.

## 검증 방법

`npm test`는 에디터 저장 동작, 업로드 큐, ZIP 경로, 내부 이동 경로,
DB 재연결, 식별자 검증, AI 권한 등의 회귀 테스트를 실행한다.
테스트에 사용하는 DB·저장소 대역은 실제 외부 서비스의 동작까지 보증하지 않는다.

- Node.js 22에서 전체 회귀 테스트 41개 통과.
- 린트 오류 0건. 기존 이미지 최적화 권고 2건은 남아 있다.
- Next.js 15.5.25 프로덕션 빌드 성공 (정적 페이지 24개 생성).
- 개발 모드 시작 및 홈 페이지 HTTP 200 확인.
- 운영 의존성 감사(`npm audit --omit=dev`) 0건. 전체 감사에는 개발 전용 전이 의존성 10건이 남아 있다.
- 임시 디렉터리에서 npm clean install과 Yarn frozen install 성공.
  PostCSS·Sharp 보안 패치는 npm overrides와 Yarn resolutions에 명시했다.
- 빌드한 앱의 홈·로그인·회원가입·약관·개인정보 페이지 HTTP 200.
  로그인→회원가입 이동, 입력 필드, 테마 유지, 모바일 가로 넘침 없음 및 화면 확대 허용 확인.
  해당 브라우저 검사에서 페이지 JavaScript 오류는 없었다.

빌드 시 기존 MongoDB 모델의 중복 hash 인덱스 선언 경고가 남아 있다.
운영 DB 인덱스는 변경하지 않았다.

실제 Chromium에서 EditorJS 최초 렌더링에 삽입한 이벤트 코드가 실행되지 않으며,
굵은 글씨·코드 블록 원문이 유지됨을 확인했다. 제목 단계의 크기도 읽기/편집 모드와
두 테마에서 확인했다. WebGL은 별도 프레임의 파일 로딩 및 부모 DOM·저장소 접근 차단을 확인했다.
PDF는 headed Chromium 비교에서 빈 sandbox가 정상 PDF 표시를 차단함을 확인하여
PDF 전용 Blob 뷰어로 처리 방식을 변경했다.
변경된 실제 PDF 컴포넌트에서 정상 PDF 표시, HTML 응답 거부, URL 변경 시 이전
Blob 해제 및 언마운트도 확인했다. Nodemailer는 Gmail 설정 생성과 메모리 내
한국어 메일 생성의 호환성을 확인했으며 실제 이메일은 발송하지 않았다.

## 후속 설계와 운영 검증이 필요한 사항

- 저장 용량 계산: 암호화 전후 크기 기준, 동시 업로드의 예약·확정 처리,
  실제 R2 객체 크기 확인을 하나의 일관된 정책으로 정리할 필요가 있다.
- 계정 삭제: 사용자, 폴더, 세션, R2 객체를 삭제하는 절차와 실패 시 재시도 정책을 함께 설계해야 한다.
- 세션 관리: 정지·삭제된 계정의 기존 access token 처리와 모든 세션 관리 경로의 토큰 검증 일관성을 추가 검토해야 한다.
- 암호화 문서의 첨부 이미지: 문서 본문과 별개로 첨부 미디어의 종단간 암호화 지원이 필요하다.
- 공유 정책: 현재는 상위 폴더에 활성 공유 링크가 있으면 파일 해시로도 접근할 수 있다.
  링크 자체의 제시를 필수로 할지는 기존 링크 호환성을 포함한 제품 정책 결정이 필요하다.
- 실제 MongoDB·R2·이메일·AI 서비스와 연동한 로그인, 공유 저장, 업로드, 복호화는 운영용 테스트 계정으로 확인해야 한다.
- PDF Blob 미리보기에는 R2의 GET CORS 허용이 필요하다. 운영 버킷에서
  `https://shareify.bonobo.kr`의 GET 요청을 허용해야 하며, 허용되지 않으면
  미리보기 오류와 다운로드 대안이 표시된다. 기존 ZIP 다운로드·복호화 역시 GET fetch를 사용하지만,
  이번 작업 환경에서 운영 버킷 설정 자체는 확인하지 못했다.

운영 데이터 삭제나 스키마 마이그레이션은 이 점검의 일부로 실행하지 않는다.
